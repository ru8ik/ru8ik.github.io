I’m a QA engineer turned software developer — testing isn’t where I came from, it’s the foundation everything else is built on. I don’t just test products, I understand how they’re built and why they break. That perspective shapes everything from how I write code to how I review someone else’s.

Experience Snapshot

  • Hands-on with JavaScript, Python, C#, automation tooling, and web delivery
  • Brings testing depth into architecture and implementation decisions

How I work

  • I write code with testability as a first-class constraint — if it’s hard to test, it’s a design problem.
  • I treat quality as an input to development, not a gate at the end.
  • I automate by risk and ROI, not to hit a coverage number.
  • I own releases end-to-end: test scope, go/no-go criteria, and rollback plan.
  • I debug by narrowing scope — reproduce it, isolate it, prove the fix holds.
  • I document decisions, not implementations; clear code doesn’t need inline narration.

These principles are reflected in my production work, automation tooling, and release-focused projects.
